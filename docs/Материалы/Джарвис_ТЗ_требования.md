# Техническое задание: голосовой ассистент «Джарвис»

> **Что это за документ.** Требования к проекту: назначение, функции, состав, критерии
> готовности и описание существующего аналогичного решения. **Способ реализации здесь
> намеренно не описывается** — его предстоит определить отдельно.
>
> **Дата:** 27 сентября 2026 г.

---

## 1. Назначение и цель проекта

**Цель:** создать персонального голосового AI-ассистента («Джарвис») — компактное
устройство, с которым можно разговаривать голосом, и которое способно выполнять реальные
задачи на компьютере пользователя.

**Ключевая идея:** устройство служит голосовым интерфейсом, а вычислительная работа
выполняется вне его. Устройство должно работать **автономно от места** — как дома, так и
за его пределами.

**Чем отличается от «умной колонки»:** помимо разговора, ассистент должен **выполнять
действия** — работать с файлами, запускать программы, выполнять команды на ПК. То есть
это не только собеседник, но и исполнитель.

## 2. Условия эксплуатации и ограничения

Это влияет на все решения, поэтому указано явно.

| Параметр | Значение |
|---|---|
| **Страна** | Россия. Часть зарубежных сервисов недоступна напрямую |
| **Пользователь** | Учащийся 10 класса. Практический опыт: пайка, ESP32/Arduino, Python, работа с API |
| **Бюджет на облачные сервисы** | **0 ₽** — только бесплатные варианты |
| **Бюджет на железо** | Ограничен, порядка 2 000–5 000 ₽ на электронику |
| **Формат** | Карманное устройство, автономное питание |
| **Основной язык** | Русский. Английский допустим как второй |
| **Условия работы** | Дома и вне дома, через точку доступа с телефона |
| **Оборудование** | Windows-ПК, смартфон Android, доступ к 3D-принтеру |

### Архитектурное требование

**Вся вычислительная часть должна размещаться вне устройства.** Устройство не должно
требовать постоянно включённого домашнего ПК для базовой работы — иначе теряется смысл
работы «вне дома».

## 3. Функциональные требования

### 3.1 Обязательные (без них проект не имеет смысла)

| № | Требование | Пояснение |
|---|---|---|
| Ф-1 | **Голосовой диалог** | Устройство слышит речь, понимает её и отвечает голосом |
| Ф-2 | **Активация по кодовому слову** | Ассистент просыпается по обращению, без нажатия кнопок |
| Ф-3 | **Своё кодовое слово** | Возможность задать индивидуальное слово (например, «Джарвис»), а не только стандартное |
| Ф-4 | **Прерывание ответа** | Возможность перебить ассистента голосом, не дожидаясь конца ответа |
| Ф-5 | **Русский язык** | Понимание русской речи и ответы на русском |
| Ф-6 | **Работа вне дома** | Устройство работает через точку доступа с телефона, без домашней сети |
| Ф-7 | **Автономное питание** | Работа от встроенного аккумулятора, зарядка по USB |
| Ф-8 | **Подключение своих языковых моделей** | Возможность использовать собственные источники моделей, а не только встроенные в сервис |
| Ф-9 | **Отсутствие обязательной платы** | Базовая работа не требует ежемесячных платежей |

### 3.2 Желательные (первая версия)

| № | Требование | Пояснение |
|---|---|---|
| Ф-10 | **Вывод информации на дисплей** | Отображение состояния и текста ответов |
| Ф-11 | **Визуальная индикация состояния** | Понятно без слов, слушает / думает / говорит / ошибка |
| Ф-12 | **Свой корпус** | Напечатанный на 3D-принтере, под конкретную компоновку |
| Ф-13 | **Управление ПК голосом** | Файлы, запуск программ, выполнение команд — по голосовой просьбе |
| Ф-14 | **Функционал уровня агента** | Способность выполнять многошаговые задачи, а не только отвечать на вопросы |
| Ф-15 | **Память о разговорах** | Сохранение контекста между сессиями |

### 3.3 Отложенные (следующие версии)

| № | Требование | Пояснение |
|---|---|---|
| Ф-16 | **Второй дисплей** | Дополнительный экран для текста, логов, графики |
| Ф-17 | **Распознавание владельца** | Ассистент реагирует только на голос пользователя |
| Ф-18 | **Связь с телефоном** | Отправка задач на смартфон и получение результатов |
| Ф-19 | **Управление умным домом** | Свет, розетки, сценарии |
| Ф-20 | **Камера («зрение»)** | Распознавание предметов, документов |

## 4. Состав системы

### 4.1 Аппаратные компоненты (первая версия)

| Компонент | Назначение | Кол-во |
|---|---|---|
| Микроконтроллер с Wi-Fi | Основной вычислительный узел устройства | 1 |
| Микрофонный модуль (цифровой) | Захват речи | 1 |
| Аудиоусилитель | Усиление сигнала для динамика | 1 |
| Динамик | Воспроизведение ответов | 1 |
| OLED-дисплей 0.96" | Отображение состояния и ответов | 1 |
| Аккумулятор Li-Pol 3.7 В | Автономное питание | 1 |
| Модуль зарядки USB Type-C | Зарядка аккумулятора | 1 |
| Выключатель питания | Включение/выключение | 1 |
| Адресный светодиод | Индикация состояния | 1–5 |
| Датчик приближения | Пробуждение при поднесении руки | 1 |
| Конденсатор по питанию усилителя | Устранение просадок и помех | 1–2 |

**Требование к микроконтроллеру:** должен обеспечивать поддержку качественной обработки
звука с эхоподавлением и индивидуального кодового слова. Это условие определяет выбор
модели.

### 4.2 Логические блоки системы

| Блок | Назначение |
|---|---|
| **Устройство** | Захват речи, индикация, воспроизведение ответов, локальное определение кодового слова |
| **Сервис распознавания и синтеза речи** | Преобразование речи в текст и текста в речь |
| **Слой языковых моделей** | Обработка смысла запроса и формирование ответа; допускает несколько источников моделей |
| **Слой инструментов** | Выполнение действий: работа с файлами, команды, запуск программ |
| **Агентский слой** | Выполнение многошаговых задач на ПК |
| **Корпус** | Защита и компоновка; требование — разнесение микрофона и динамика для работы эхоподавления |

## 5. Критерии готовности

Критерии сформулированы проверяемо — каждый можно подтвердить или опровергнуть.

### 5.1 Критерии первой версии

| № | Критерий | Как проверяется |
|---|---|---|
| Г-1 | Устройство активируется по кодовому слову | Произнести кодовое слово — устройство реагирует индикацией |
| Г-2 | Речь распознаётся на русском | Произнести 10 коротких фраз — не менее 8 распознаны верно |
| Г-3 | Ответ озвучивается на русском | Ассистент отвечает вслух, речь разборчива |
| Г-4 | Задержка ответа приемлема | Ответ начинается не позднее 4 секунд после окончания фразы |
| Г-5 | Ответ можно прервать голосом | Начать говорить во время ответа — ассистент замолкает и слушает |
| Г-6 | Работает от аккумулятора | Не менее 2 часов непрерывной работы без подзарядки |
| Г-7 | Заряжается по USB | Зарядка от стандартного USB-адаптера |
| Г-8 | **Работает вне дома** | Выйти из дома с точкой доступа телефона — устройство продолжает работать без ручной перенастройки |
| Г-9 | Подключается своя языковая модель | Диалог идёт через собственный источник моделей; смена источника не требует изменения устройства |
| Г-10 | Нет обязательных платежей | Всё перечисленное работает при нулевых ежемесячных расходах |
| Г-11 | Устройство помещается в руке | Габариты соответствуют карманному формату |
| Г-12 | Индикация состояния различима | По свечению понятно, что происходит, без взгляда на экран |

### 5.2 Критерии второго этапа (управление ПК)

| № | Критерий | Как проверяется |
|---|---|---|
| Г-13 | Ассистент выполняет файловые операции | «Найди файл с прошлой недели» — файл найден и назван |
| Г-14 | Ассистент запускает программы | «Открой проект» — программа запущена |
| Г-15 | Ассистент выполняет многошаговую задачу | Задача из 3+ шагов выполнена без дополнительных указаний |
| Г-16 | **Управление ПК работает извне** | Команда отдана вне дома — ПК её выполнил |
| Г-17 | Действия ограничены по области | Попытка выйти за разрешённые папки/операции блокируется |
| Г-18 | Ассистент реагирует только на владельца | Голос другого человека не активирует управление ПК |
| Г-19 | Все вызовы инструментов логируются | Есть журнал: что, когда и по какой просьбе выполнено |

### 5.3 Общий критерий проекта

**Проект считается достигшим цели, если:** пользователь может достать устройство из
кармана в любом месте, сказать «Джарвис, …» и получить голосовой ответ, а при наличии
включённого ПК — ещё и выполнение задачи на этом ПК. Всё это — без ежемесячных платежей.

## 6. Существующее аналогичное решение

### 6.1 Что это

**xiaozhi-esp32** — открытый проект голосового AI-ассистента на микроконтроллерах ESP32.
Лицензия MIT (свободное использование, включая коммерческое). Именно на нём основан
проект-референс, с которого началась разработка.

### 6.2 Назначение

Дать возможность собрать собственного голосового ассистента на недорогом
микроконтроллере, не разрабатывая с нуля ни устройство, ни серверную часть.

### 6.3 Возможности

| Возможность | Описание |
|---|---|
| Голосовой диалог | Полный цикл: распознавание речи → языковая модель → синтез речи |
| Локальное кодовое слово | Определение кодового слова на самом устройстве, без интернета |
| Индивидуальные кодовые слова | Возможность задать своё слово вместо стандартного |
| Поддержка множества плат | Более 130 конфигураций плат, включая готовые под типовые наборы компонентов |
| Вызов инструментов | **MCP** — открытый протокол, позволяющий модели вызывать инструменты как на устройстве, так и во внешних системах |
| Управление устройством | Кнопки, светодиоды, GPIO, сервоприводы — доступны как инструменты |
| Управление умным домом | Интеграция с системами умного дома |
| Дисплеи и анимации | Поддержка OLED/LCD, система эмодзи и выражений |
| Распознавание говорящего | Определение, кто именно говорит |
| Управление питанием | Отображение заряда, энергосбережение |
| Множество языков | Интерфейс и голосовые подсказки на многих языках, включая русский |
| Два транспорта связи | WebSocket и MQTT+UDP |
| Открытые серверные реализации | Несколько независимых серверов (Python, Java, Go) для самостоятельного развёртывания |

### 6.4 Экосистема вокруг проекта

- **Серверные реализации** — позволяют не зависеть от официального облака и подключать
  любые модели, включая локальные.
- **Готовые платы** — эталонные устройства от разных производителей.
- **Инструменты кастомизации** — редакторы кодовых слов, шрифтов, эмодзи.

### 6.5 Чем наш проект отличается

| Аспект | xiaozhi-esp32 | Проект «Джарвис» |
|---|---|---|
| **Основной язык** | Приоритет — китайский и английский | **Приоритет — русский** |
| **Способ работы** | Официальное облако или свой сервер | **Полностью облачный**, с возможностью подключения своих моделей |
| **Работа вне дома** | Не акцентируется | **Обязательное требование** |
| **Управление ПК** | Возможно, но не является целью | **Является ключевой целью** — функционал уровня агента |
| **Связь с готовым агентом** | Отсутствует | **Интеграция с уже имеющимся агентом** на ПК |
| **Бюджет** | Не регламентирован | **Строго 0 ₽** на облачные сервисы |
| **Формат** | Разные, включая настольные | **Карманный**, с автономным питанием |
| **Индикация** | Экран | Экран **плюс** световая индикация состояния |
| **Безопасность управления ПК** | Не регламентирована | **Отдельные требования** (Г-17, Г-18, Г-19) |

**Кратко:** xiaozhi-esp32 — это готовая техническая основа. Наш проект — это
**специализация под конкретные задачи**: русский язык, работа вне дома, нулевой бюджет
и управление ПК как основная цель, а не дополнительная возможность.

## 7. Что не входит в проект

- Разработка собственного протокола связи или собственной модели распознавания речи.
- Промышленное производство и сертификация.
- Поддержка нескольких пользователей одновременно.
- Работа полностью без интернета (при выбранной облачной схеме это осознанное ограничение).
- Коммерческое использование.

---

## 8. Приоритеты при компромиссах

Если придётся чем-то жертвовать, порядок важности такой:

1. **Голосовой диалог на русском** — без этого проекта нет.
2. **Работа вне дома** — иначе теряется основная ценность.
3. **Нулевая стоимость** — жёсткое ограничение.
4. **Управление ПК** — вторая по значимости цель.
5. Всё остальное — по возможности.
