# 14 Бриф для внешней модели (GPT-6 Sol)

← [[Джарвис — карта проекта]]

**Назначение.** Самодостаточное ТЗ для внешней модели: проверить факты и собрать
архитектуру, на которую можно опираться. Всё, что нужно, — ниже; контекст чата не требуется.

**Скопировать целиком в новую сессию.**

---

## ЗАДАЧА

Спроектировать реалистичную архитектуру персонального голосового AI-ассистента
(«Джарвис») и проверить приведённые ниже факты. Отдельно указать, **какие из них
неверны или устарели**, и что делать вместо них.

**Требуется на выходе:**
1. Список опровергнутых/уточнённых фактов (с источниками).
2. Архитектурная схема: что работает на устройстве, что на сервере, что в облаке.
3. Стек по слоям (wake word / VAD / ASR / LLM / TTS / инструменты / память) с обоснованием.
4. Порядок сборки: этапы так, чтобы **каждый заканчивался работающим результатом**.
5. Таблица рисков с планами Б.
6. Явный ответ: закрывается ли требование «работает вне дома при 0 ₽», и как именно.

---

## КОНТЕКСТ

Пользователь — **учащийся 10 класса, Москва, РФ**. Опыт: пайка, ESP32/Arduino, Python,
работа с API. Есть Windows-ПК, Android-телефон, 3D-принтер. Есть разобранная
Яндекс Станция Лайт (донор).

**Ограничения (жёсткие):**
- Бюджет на облачные сервисы: **0 ₽/мес**
- Бюджет на железо: **2 000–5 000 ₽**
- Формат: **карманное** устройство, автономное питание
- Язык: **русский** (основной), английский — второй
- Работа **дома и вне дома** (через точку доступа телефона)
- Базовая работа **не должна требовать постоянно включённого домашнего ПК**
- Страна: Россия (часть зарубежных сервисов недоступна напрямую)

**Приоритеты при компромиссах (в этом порядке):**
1. Русский голосовой диалог — без него проекта нет
2. Работа вне дома
3. Нулевая стоимость
4. Управление ПК голосом
5. Всё остальное — по возможности

## ТРЕБОВАНИЯ

**Обязательные:** Ф-1 голосовой диалог · Ф-2 активация кодовым словом ·
Ф-3 **своё** кодовое слово (например «Джарвис») · Ф-4 **перебивание голосом** ·
Ф-5 русский язык · Ф-6 работа вне дома · Ф-7 автономное питание, зарядка USB ·
Ф-8 подключение своих языковых моделей · Ф-9 отсутствие обязательных платежей.

**Желательные:** Ф-10 дисплей · Ф-11 световая индикация · Ф-12 корпус (3D-печать) ·
Ф-13 управление ПК голосом · Ф-14 многошаговые задачи · Ф-15 память диалога.

**Критерии приёмки:** Г-1 реакция на кодовое слово · Г-2 ≥8 из 10 русских фраз
распознаны верно · Г-3 ответ вслух разборчив · **Г-4 ответ начинается ≤4 с** от конца
фразы · Г-5 можно перебить голосом · Г-6 ≥2 ч от аккумулятора · Г-7 зарядка USB ·
Г-8 работает вне дома без перенастройки · Г-9 смена источника моделей без перепрошивки ·
Г-10 ноль ежемесячных расходов · Г-11 карманный формат · Г-12 различимая индикация ·
Г-13…Г-19 управление ПК: файлы, запуск программ, многошаговость, работа извне,
ограничение области, только владелец, журнал вызовов.

## ПРОВЕРЕННЫЕ ФАКТЫ (проверено 04.10.2026 по первоисточникам)

### Прошивка xiaozhi-esp32 (`github.com/78/xiaozhi-esp32`)
- Лицензия **MIT**. Требует **ESP-IDF ≥ 6.0.1**, рекомендуется 6.1; IDF 5.x не поддерживается.
- Чипы: ESP32, C3, C5, C6, S3, P4 (+ сборки под S31 требуют IDF 6.1).
- Транспорты: **WebSocket** и **MQTT+UDP**. Аудио — Opus.
- **MCP двусторонний:** device-side (управление устройством) и cloud-side (умный дом,
  **управление ПК**, поиск, почта).
- **138 конфигураций плат, 171 вариант сборки.** Есть board **`bread-compact-wifi`**:
  ESP32-S3 + OLED 128×64 + I2S-микрофон + I2S-усилитель.
- Прямая цитата: «AEC-capable hardware supports realtime full-duplex interaction».
- Распознавание диктора — **3D Speaker**. 39 языков **интерфейса**.

### ESP-SR (`github.com/espressif/esp-sr`)
- **AFE (в т.ч. AEC) поддерживается только на ESP32, ESP32-S3, ESP32-P4, ESP32-S31.**
  У C3/C5/C6/S2 — **нет**.
- **MultiNet** (распознавание команд, до 300) — только S3/P4/S31.
- У C3/C5 — только модель **WakeNet9s** (без PSRAM/SIMD).
- **Русских моделей WakeNet/MultiNet не существует** — только китайский/английский.

### Сервер xiaozhi-esp32-server (`github.com/xinnan-tech/xiaozhi-esp32-server`)
- Лицензия **MIT**.
- Требования: минимальная установка — **2 ядра / 2 ГБ** (только API) или **2 ядра / 4 ГБ**
  (с локальным FunASR); полная — 4/8 или 2/4.
- ASR: локально FunASR, SherpaASR; по API — FunASRServer, Volcano, iFlytek, Tencent,
  Alibaba, Baidu, OpenAI ASR.
- TTS: **EdgeTTS** (бесплатно) + много облачных; локально FishSpeech, GPT-SoVITS, Index-TTS, PaddleSpeech.
- VAD: **SileroVAD**. Диаризация: **3D-Speaker**.
- LLM: любые OpenAI-совместимые, Ollama, Dify, FastGPT, Coze, Xinference, HomeAssistant.
- MCP: поддерживается «точка подключения».
- Память: `mem_local_short` (бесплатно), mem0ai, PowerMem.
- **Русского языка в проекте нет** (переводы: zh, en, vi, de, pt-BR).
- Заявлено: **«не production-ready, не проходил аудит безопасности»**.

### Доступность xiaozhi из РФ (проверено живыми запросами + Cloudflare DoH)
- `xiaozhi.me` → **200**, резолвится (47.83.164.0) — **сайт доступен из РФ**.
- `xiaozhi.ru` → резолвится (194.58.112.174), но **502 Bad Gateway**.
- `ota.xiaozhi.ru`, `mqtt.xiaozhi.ru`, `ws.xiaozhi.ru` → **NXDOMAIN** (записей не существует).
- Русская адаптация `github.com/ZDarow/xiaozhi-esp32` (ветка `feature/russia-adaptation`,
  создан 11.09.2026) прописывает эти мёртвые адреса по умолчанию и сама предупреждает об этом.
- Регистрация на xiaozhi.me завязана на **номер телефона** (из офиц. справки);
  приём российского номера **не проверен**.

### Русские ASR/TTS
- **Groq `whisper-large-v3-turbo`**: free-tier **20 RPM, 2000 RPD, 28 800 аудио-сек/день (8 ч)**.
- **Vosk**: `vosk-model-ru-0.42` — 1,8 ГБ, WER 4,5–19,5; `vosk-model-small-ru-0.22` —
  45 МБ, WER 22–32. Apache-2.0. Есть spk-модель (13 МБ) для распознавания говорящего.
- **GigaAM v3** (Sber): **MIT**, 220–600M параметров, SOTA-русский, экспорт в ONNX,
  требует CPU/GPU.
- **edge-tts** — бесплатно, ru-RU голоса, без ключа. **Silero TTS**, **Piper** — локальные ru-голоса.

### Speech-to-speech API
- **OpenAI Realtime** и **Gemini Live**: одна модель работает со звуком напрямую,
  дают barge-in и низкую задержку «из коробки», есть function calling и MCP.
- Gemini Live: WebSocket, 70 языков. **Оба недоступны из РФ без VPN и платные**
  (у Gemini есть free-tier в AI Studio).

### Референс: полностью локальный агент на Pi (brenpoly/be-more-agent, MIT)
- Raspberry Pi 5 16 ГБ + Ollama (Gemma 3 1–2B) + whisper.cpp + **OpenWakeWord** + **Piper**.
- Конечный автомат: IDLE / LISTENING / THINKING / SPEAKING / ERROR / CAPTURING / **WARMUP**.
- Инструменты: LLM выдаёт JSON `{"action":…,"value":…}` по примерам в системном промпте;
  белый список + таблица алиасов для галлюцинаций. По сути — MCP своими руками.
- Кодовое слово: README обещает «Hey Jarvis», но модель фактически обучена на
  **«Hey BMO»** (открытый issue #26) — то есть готового «Hey Jarvis» нет.
- Автор сравнил ускорители (Hailo-10H 40 TOPS vs M5Stack LLM-8850 24 TOPS) и
  **остался на голом CPU**: ускорители запирают в узкий набор предустановленных моделей.
- ⚠️ Апстрим **заморожен** с 11.04.2026; активные форки живут (например `moorew/be-more-hailo`).

## НЕПРОВЕРЕННЫЕ ГИПОТЕЗЫ (требуют проверки — не принимать на веру)

1. **Русский ASR/TTS в облаке xiaozhi.me.** Сторонний сайт `xiaozhi.dev/ru` заявляет
   «многоязычное ASR (КН/АН/ЯП/КР/РУ)», но это **не официальный источник**, и в его же
   таблице метрик точность указана для **китайского**. В официальном README про русский
   ASR/TTS — ничего. **Считать отсутствующим, пока не проверено на устройстве.**
2. **Точка подключения MCP на бесплатном тарифе xiaozhi.me.** Не подтверждена.
3. **Регистрация на xiaozhi.me с российского номера.** Не проверена.
4. **Производительность Termux + proot-distro + onnxruntime/sherpa-onnx на Android.**
   Требование «2 ядра / 4 ГБ» — для x86 и FunASR; замеров на ARM под proot нет.
   Termux работает на Bionic (не glibc), поэтому колёса pip под ARM64 не ставятся.
5. **Доступность Oracle Cloud Always Free из РФ** (нужна карта, возможен VPN).
6. **Раздаёт ли конкретный Android-телефон хотспот на 2,4 ГГц** (ESP32-S3 не видит 5 ГГц).

## УЖЕ ПРИНЯТЫЕ РЕШЕНИЯ (не пересматривать без причины)

- Устройство — **ESP32-S3 N16R8** (8 МБ PSRAM обязательны для AFE). Не C3 (нет AEC), не Pi.
- Архитектура — **хаб + спутник** (как у Alexa / Алисы / Home Assistant).
- Прошивка — **xiaozhi-esp32** (MIT), своя board-конфигурация.
- LLM — **свой OpenAI-совместимый источник** (`base_url` + key + model), 2–3 профиля
  с автопереключением. У пользователя уже работает **Cloudflare Worker**, проксирующий
  NVIDIA и OpenRouter (проверено живьём: ответ модели за 1,35 с, ключ спрятан внутри).
- Донор (Яндекс Станция Лайт) — берём **корпус, динамик 4 Ω 5 Вт, блок питания**;
  плату — нельзя (secure boot, закрытая документация, привязка аккаунта).
- Корпус — **3D-печать**.
- Порядок — **сначала диалог, потом корпус и батарея**.

## ЧТО УЖЕ ОПРЕДЕЛЕНО КАК ПРОБЛЕМЫ (нужны решения)

1. **«0 ₽» + «облако» + «вне дома»** — треугольник не сходится без компромисса.
   Предлагалось: свой сервер на ПК (дома) + Oracle Cloud Always Free (вне дома),
   резерв — Cloudflare Worker как транспорт.
2. **Русское кодовое слово на ESP32 невозможно** (нет русских моделей WakeNet/MultiNet).
   Предлагалось: **openWakeWord на хабе** (готовая модель «hey jarvis») либо штатное
   слово прошивки, либо кнопка.
3. **AEC/перебивание в карманном корпусе** — акустически трудно. Предлагалось:
   не делать критерием выхода, план Б — push-to-talk.
4. **TP4056 не даёт load-sharing** (нельзя заряжать и работать одновременно).
   Предлагалось: IP5306 / модуль с power-path.
5. **Второй дисплей** прошивкой не поддерживается. Предлагалось: светодиодное кольцо WS2812.
6. **Octal-PSRAM на N16R8 занимает GPIO 33–37** — учесть в board-конфигурации.

## ЧТО ИМЕННО ПРОВЕРИТЬ

1. Все факты из раздела «ПРОВЕРЕННЫЕ» — с указанием, что устарело.
2. Все шесть гипотез из «НЕПРОВЕРЕННЫХ» — по возможности закрыть.
3. Реалистичность Г-4 (≤4 с) на цепочке «хотспот → бесплатный ASR → free-tier LLM → TTS»
   без стриминга. Если недостижимо — что нужно изменить.
4. Есть ли путь закрыть Г-8 (вне дома) за 0 ₽ **без** Termux и **без** платного хостинга.
5. Достаточно ли 2 000–5 000 ₽, чтобы закрыть Г-1…Г-12.

## ЧЕГО НЕ ДЕЛАТЬ

- Не предлагать платные сервисы (нарушает Ф-9/Г-10).
- Не предлагать сервисы, недоступные из РФ без VPN (OpenAI Realtime, Gemini Live) —
  как основной путь; только как «апгрейд, если появится доступ».
- Не ставить в критический путь непроверенные гипотезы (Termux+proot, русское
  кодовое слово, MCP в free-консоли).
- Не предлагать локальный LLM на ESP32 — физически невозможно.
- Не проектировать «с нуля»: хаб-спутниковая схема уже подтверждена практикой.
