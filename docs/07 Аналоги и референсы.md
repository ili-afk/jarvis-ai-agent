# 07 Аналоги и референсы

← [[Джарвис — карта проекта]]

Исследование 04.10.2026 по первоисточникам (репозитории, официальная документация).
Ниже — как устроены существующие голосовые AI-агенты на микроконтроллерах и вокруг них.

---

## Главный вывод: архитектура у всех одна

Все промышленные и открытые голосовые ассистенты (Alexa, Алиса, Home Assistant Voice,
xiaozhi, Willow) построены по одной схеме:

```
[Спутник: микрофон + динамик + экран]  ← «глупое» устройство, только звук и железо
              │  аудиопоток (Opus/PCM)
              ▼
[Хаб: ASR → LLM → TTS + инструменты]   ← вся вычислительная работа
              │
              ▼
[Действия: умный дом, ПК, поиск]
```

**Ваш план v1 угадал эту схему правильно.** Это его сильная сторона — и это же
подтверждает, что не нужно изобретать архитектуру, нужно лишь правильно выбрать,
где какой компонент живёт.

## Разбор по проектам

### xiaozhi-esp32 (основа вашего проекта)

**Проверено по README 04.10.2026:**
- Поддерживаемые чипы: **ESP32, C3, C5, C6, S3, P4** (+ сборки под S31 требуют IDF 6.1).
- Протоколы: **WebSocket** и **MQTT+UDP**.
- **MCP в двух направлениях:** device-side (управление устройством) и cloud-side
  (расширение модели — умный дом, **управление ПК**, поиск, почта).
- **138 конфигураций плат**, 171 вариант сборки. Есть `bread-compact-wifi` — ровно
  ваш набор (S3 + OLED 128×64 + I2S-микрофон + I2S-усилитель).
- Лицензия **MIT**, включая коммерческое использование.
- Требует **ESP-IDF ≥ 6.0.1** (рекомендуется 6.1); IDF 5.x не поддерживается.
- Прямая цитата из README: «**AEC-capable hardware supports realtime full-duplex
  interaction**» — перебивание зависит от железа.
- 39 языков интерфейса; распознавание говорящего — **3D Speaker** (modelscope).
- Поддерживает **Realtime end-to-end голосовые модели** (помимо классического ASR+LLM+TTS).

### xiaozhi-esp32-server

**Проверено по README 04.10.2026:**
- **Лицензия MIT** ✅ — риск из плана v1 закрыт.
- Требования: минимальная установка — **2 ядра / 2 ГБ** (только API) или **2 ядра / 4 ГБ**
  (с FunASR). Полная — 4/8 или 2/4.
- **ASR:** локально FunASR, SherpaASR; через API — FunASRServer, Volcano, iFlytek,
  Tencent, Alibaba, Baidu, OpenAI ASR.
- **TTS:** EdgeTTS (бесплатно), много облачных; локально FishSpeech, GPT-SoVITS, Index-TTS, PaddleSpeech.
- **VAD:** SileroVAD. **Диаризация:** 3D-Speaker.
- **LLM:** OpenAI-совместимые, Ollama, Dify, FastGPT, Coze, Xinference, HomeAssistant.
- **MCP:** поддерживается «MCP-точка подключения».
- **Память:** mem_local_short (бесплатно), mem0ai, PowerMem.
- ⚠️ **Русского языка в проекте нет** — ни в интерфейсе, ни в документации. Переводы:
  zh, en, vi, de, pt-BR.
- ⚠️ Заявлено: **«не production-ready, не проходил аудит безопасности»**.

### Home Assistant Assist + Wyoming (альтернативная ветка)

- **Wyoming** — открытый протокол (JSONL + PCM по TCP). Каждый сервис — **отдельный процесс**:
  wake word, ASR, TTS, intent, VAD, satellite. Это «правильная» декомпозиция.
- **Assist pipeline:** wake word → STT → intent → TTS. Запускается по WebSocket API.
- **Спутники:** ESPHome-устройства с компонентом `voice_assistant`; на устройстве —
  micro_wake_word, микрофон, динамик; всё остальное — в HA.
- ⚠️ Wyoming **без аутентификации и шифрования по замыслу** — только доверенная сеть.
- **Русский:** Whisper (STT) и Piper (TTS) имеют ru-модели → русский диалог возможен.
- **Ценность для вас:** это готовая, зрелая альтернатива xiaozhi-ветке. Если xiaozhi
  окажется неудобен для русского — Wyoming + Whisper + Piper закрывает задачу.
- 🔎 Приятная деталь: в HA стандартное кодовое слово — **«Hey Jarvis»**. Ваше имя проекта
  уже существует как штатный wake word.

### Willow (ESP32-S3)

- Устройство — ESP32-S3; сервер — **Willow Inference Server** (STT/TTS/LLM), self-hosted.
- Архитектура та же: спутник + сервер. Подробная документация — `heywillow.io`.

### Speech-to-speech API (OpenAI Realtime, Gemini Live)

- **Принципиально другая архитектура:** нет отдельных ASR → LLM → TTS; одна модель
  работает напрямую со звуком. Даёт **перебивание и низкую задержку «из коробки»**.
- Транспорт: WebRTC или WebSocket. Есть function calling и MCP.
- 🔴 **Но:** и OpenAI, и Google недоступны из РФ без VPN, и оба платные
  (у Gemini есть free-tier в AI Studio).
- **Вывод:** это «идеальное» решение по качеству, но **не для проекта с 0 ₽ и из РФ**.
  Держать в голове как апгрейд, если появится доступ.

## Чему учит сравнение (выводы для проекта)

1. **Хаб + спутник — единственно верная схема.** Ваш план v1 её угадал.
2. **Всё, что дорого и рискованно, надо убирать с устройства** — и это делают все:
   у Alexa на устройстве только wake word, у HA-спутника только micro_wake_word.
3. **Русский — не экзотика.** Whisper, Piper, Vosk, GigaAM его знают. Проблема не в языке,
   а в том, **где** это считать (0 ₽ → облако).
4. **Никто не делает своё кодовое слово на русском на ESP32.** Это подтверждает вывод A3.
5. **Декомпозиция Wyoming — хороший образец** для вашего оркестратора: ASR, TTS, wake word
   как отдельные заменяемые модули. Именно так и надо писать свой код.
6. **xiaozhi-esp32-server — MIT и подходит**, но у него нет русского и он «не production-ready».
   Использовать как готовую периферию, а не как догму.
