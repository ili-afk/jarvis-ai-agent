## Схема

```
[Джарвис: ESP32-S3 + OLED 0.96" + WS2812 + Li-Pol]
        │  Wi-Fi (точка доступа телефона), WebSocket, аудио в Opus
        ▼
[Сервер-оркестратор — Termux → proot-distro Ubuntu (на том же телефоне)]
        ├── SileroVAD      — режет поток по тишине
        ├── SherpaASR      — речь → текст (русская модель)
        ├── LLM            — OpenAI-совместимый, free-tier
        ├── EdgeTTS        — текст → речь (ru-RU)
        ├── 3D-Speaker     — «кто говорит» → основа для Г-18
        └── MCP-шлюз
                 │  исходящее соединение (туннель не нужен)
                 ▼
        [MCP-агент на Windows-ПК: файлы, команды, запуск программ]
```

**Ключевое свойство:** прошивка устройства знает ровно один адрес. Смена ASR/LLM/TTS —
правка конфига на сервере; устройство не перепрошивается. Это и есть Ф-8/Г-9.

---

## Три отклонения от видео-ориентира (Huy Vector, ESP32-C3)

| Что у автора видео | Почему нам нельзя | Что берём вместо |
|---|---|---|
| ESP32-C3 | ESP-SR (WakeNet + AFE) на C3 урезан: нет AEC → нет перебивания (Ф-4) | **ESP32-S3 N16R8** (8 МБ PSRAM) |
| Облако xiaozhi.me | Нельзя подключить свои модели (Ф-8), есть квота → 0 ₽ не гарантирован | **Свой сервер** xiaozhi-esp32-server |
| Латунная рама | Пайка каркаса вручную не воспроизводима | 3D-печать (Ф-12) |

> ✅ Это **верное** решение, подтверждено первоисточником ESP-SR (см. [[07 Аналоги и референсы]]):
> AFE с AEC есть только у ESP32, S3, P4, S31. У C3 — только WakeNet9s, без AEC.
> Но из этого же факта следует риск: AFE/AEC на S3 — самая тяжёлая часть (см. аудит).

## Стек v1

| Слой | Решение | Обоснование |
|---|---|---|
| Оркестратор | `xinnan-tech/xiaozhi-esp32-server` (Python), из исходников | Docker в Termux недоступен |
| ASR | SherpaASR (sherpa-onnx), русская модель | FunASR ориентирован на китайский/английский |
| VAD | SileroVAD | Единственный в сервере |
| TTS | EdgeTTS, ru-RU | Ключ не нужен |
| LLM | OpenAI-совместимый free-tier | Ф-8/Г-9 = поле `base_url` |
| Голос владельца | 3D-Speaker | Уже встроен → закрывает Г-18 |
| Память | `mem_local_short` | Локальная, бесплатная |
| Инструменты | MCP (клиентский, серверный, «точка доступа») | Управление ПК — штатная возможность |
| Прошивка | `78/xiaozhi-esp32`, MIT, ESP-IDF 6.1 | Требует IDF ≥ 6.0.1 |

Требования сервера по документации: **2 ядра / 2 ГБ** (только API),
**2 ядра / 4 ГБ** (с локальным FunASR). Оценка 4 ГБ — для FunASR на x86;
sherpa-onnx легче, но замер не делался.

## Этапы v1

| Этап | Что делаем | Критерий выхода |
|---|---|---|
| M0 | ESP32-S3 devkit + штатная прошивка + xiaozhi.me | Сквозной диалог с облаком |
| M1 | Termux → proot Ubuntu → сервер из исходников | Устройство подключается к своему серверу |
| M2 | Русский ASR + EdgeTTS ru-RU | 8 из 10 фраз верно |
| M3 | Своё кодовое слово | Реакция на «Джарвис» |
| M4 | AFE/AEC: включить аудиопроцессор, разнести мик/динамик | Перебивание работает |
| M5 | Аккумулятор, зарядка, корпус | 2 ч работы, габариты |
| M6 | MCP-агент на ПК, ограничения, журнал | Файлы, программы, песочница |
| M7 | Память диалога | Контекст между сессиями |

Правильный принцип: **M0 → M1 → M2 раньше корпуса и батареи.**

## Альтернативная ветка v1 — «всё в облаке»

Отдельный документ `Материалы/Джарвис_облачная_схема.md` описывает второй путь:

```
ESP32-S3 → облако xiaozhi.me (ASR + TTS, бесплатно) → ваш Cloudflare Worker → NVIDIA/OpenRouter
```

- Заменяется **только LLM**; ASR и TTS остаются встроенными в китайское облако.
- Точка подключения **MCP выдаётся в консоли xiaozhi.me** → управление ПК без своего сервера.
- Подводный камень: точка доступа телефона должна быть **2,4 ГГц**.

> ⚠️ Две ключевые гипотезы этой ветки **не проверены**: (1) есть ли раздел MCP в
> **бесплатной** консоли; (2) качество **русского** ASR/TTS в xiaozhi.me.
> Обе — в списке рисков.
