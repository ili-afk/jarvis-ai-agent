## Хронология ключевых решений

### 21.09 — Первое проектирование

- Сформулирована идея: ассистент «как Яндекс-колонка, но агент», со своим API-ключом.
- **Принято решение: архитектура «хаб + спутники»** — один всегда включённый «мозг»,
  устройства только захватывают и играют звук. Обоснование: общая память между
  устройствами, смена модели в одном месте, продолжение разговора на другом устройстве.
- Транспорт: **WebSocket по локальной сети**; для телефона вне дома — Tailscale.
- Выбран стек речи: openWakeWord / Silero VAD / Groq Whisper / edge-tts,
  апгрейд-путь до GigaAM и Yandex SpeechKit.
- Сформулирован механизм перебивания: очередь реплик + VAD во время проигрывания +
  состояние «на чём прервали» уходит в следующий промпт.
- Исправлена концепция «ПК ускоряет облако» → **capability-aware router**.
- Определены модули: папка + `manifest.json` + класс с `handle()`, уровень прав
  auto / confirm / deny.
- Роадмап M0–M6. **Правило: не начинать с M4 (корпуса).**

### 21.09 — Разбор донора

- **YENDX-00025 = Яндекс Станция Лайт.** Нет USB-порта вообще (только питание).
- Прошивка не взламывается: MediaTek SoC, подписанный загрузчик, ~512 МБ RAM.
- **Вывод: сохранить корпус, динамик, микрофоны; электронику заменить.**

### 26.09 — Список покупок и VENTUNO Q

- Опознано видео-ориентир: **Huy Vector, «Tiny Pocket AI Assistant»** (27.08.2026),
  ESP32-C3 + OLED + латунный корпус, AI — **облако xiaozhi.me**.
- Составлен список покупок с ценами РФ.
- Разобран **Arduino VENTUNO Q**: это **не апгрейд** (160×100 мм, 7–24 В, 4–26 мин от батареи,
  ~$299) — отдельный проект «настольный AI-хаб».
- **Найдено в коде прошивки** (`main/Kconfig.projbuild`): полноценный wake word с AEC
  требует **ESP32-S3/P4 + PSRAM**. На C3 — урезанный режим.
- Разобран донор по фото: плата `JUW7.820.10012833`, усилитель `NTP8910A`,
  динамик `LY3286` 4 Ω 5 Вт, дефект `DD15` = MP1605GTF-Z.
- **Вывод: плату использовать нельзя** (secure boot, нет документации, привязка аккаунта).
- Разобрано видео про Irbis A + Home Assistant + Wyoming — **важная альтернатива**.
- Ремонт донора: припой Sn63Pb37 0,5 мм, флюс ЛТИ-120, сплав Розе для снятия,
  либо обход — модуль XM1584 на 1,15 В.
- **Найдено: в облаке xiaozhi.me можно подставить свой LLM** (base_url + key + model).
- **Найдено: точка подключения MCP выдаётся в консоли xiaozhi.me**, ПК подключается
  исходящим соединением → не нужен проброс портов.
- ⚠️ Но: заменяется **только LLM**; ASR и TTS остаются встроенными. И это **не проверено
  для бесплатного тарифа**.

### 26–27.09 — Проверка API-обхода из РФ (самое ценное)

- **Живая проверка 27.09:** ваш Worker `hermes-or-proxy` успешно проксирует OpenRouter —
  реальный ответ модели, ключ спрятан внутри (поддельный ключ тоже даёт 200).
- **NVIDIA через Worker работает**: `nvidia/nemotron-3-super-120b-a12b` ответил за **1,35 с**.
- **Опровергнут старый вывод** («прокси через Worker принципиально не работает»):
  в августе было 403, сейчас — 200.
- **Критично для голоса:** проверена буферизация. Сквозная передача (`resp.body`) отдаёт
  токены по мере поступления — это то, что нужно для низкой задержки.
- Вывод: блокировки изменчивы → **держать 2–3 пути и перепроверять**.

## Что решено окончательно

1. Платформа устройства — **ESP32-S3 N16R8** (не C3, не PENTUNO).
2. Архитектура — **хаб + спутник**.
3. Прошивка — **xiaozhi-esp32 (MIT)**.
4. LLM — **свой OpenAI-совместимый источник через Cloudflare Worker**.
5. Донор — берём **корпус, динамик, БП**; плату — нет.
6. Корпус — **3D-печать** (не латунь).
7. Порядок — **диалог раньше корпуса и батареи**.

## Что решено НЕ было (и решается в v2)

- Где физически живёт оркестратор (Termux / ПК / облако) — **не выбрано**.
- Как быть с русским кодовым словом — **предложено неверное решение**.
- Как обеспечить Г-8 при 0 ₽ — **не выбрано**.
- Что делать, если Termux+ASR не заработает — **нет плана Б**.
