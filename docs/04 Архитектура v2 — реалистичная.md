# 04 Архитектура v2 — реалистичная

← [[03 Аудит — что не так с планом v1]] · далее → [[08 План доведения до рабочего решения]]

## Принцип, который всё меняет

Вместо одной большой архитектуры, которая «сработает или нет», — **лестница из 4 ступеней.
Каждая ступень полезна сама по себе, и на каждой есть работающий результат.**

Это снимает главную проблему v1: три самых рискованных элемента (Termux+ASR, русское
кодовое слово, AEC) перестают быть воротами — их можно отложить и заменить.

```
Ступень 0  →  Ступень 1  →  Ступень 2  →  Ступень 3
ПК, текст     ПК, голос     ESP32-S3      Вне дома
(дни)         (дни)         (недели)      (по ситуации)
   │             │             │             │
   └─ проверяет ─┴─ проверяет ─┴─ проверяет ─┘
      пайплайн      диалог        железо       мобильность
```

---

## Ступень 0 — Ассистент на ПК, текстом (1–2 вечера, 0 ₽, без железа)

**Цель:** доказать, что пайплайн «вопрос → LLM → ответ» работает с **вашими** ключами,
и получить фундамент, который потом переиспользуется.

```
Вы (терминал) → оркестратор (Python на ПК) → ваш Cloudflare Worker → NVIDIA / OpenRouter
                        │
                        └── SQLite: история диалога (Ф-15)
                        └── MCP-инструмент: ask_hermes(вопрос) → Hermes на ПК (Ф-13/Ф-14)
```

**Почему так:** Cloudflare Worker + NVIDIA/OpenRouter — **единственная часть стека,
которая уже проверена живьём** (27.09: реальный ответ модели за 1,35 с). Начинать надо
с того, что уже работает, а не с того, что может не заработать.

**Что закрывает:** Ф-8, Ф-9, Ф-15, частично Ф-13/Ф-14.
**Что проверяет:** что ваши ключи и обёртка годятся как мозг ассистента.

---

## Ступень 1 — Ассистент на ПК, голосом (несколько вечеров, 0 ₽)

**Цель:** получить **полноценный голосовой диалог по-русски** до того, как куплена
хоть одна деталь. Это тот самый «минимально демонстрируемый продукт».

```
Микрофон ПК → Silero VAD → ASR (Groq Whisper large-v3-turbo, free)
                                    ↓
Динамики ПК ← TTS (edge-tts, ru-RU) ← LLM (ваш Worker)
                    ↑
        перебивание: VAD слушает во время проигрывания,
        очередь реплик обрезается, состояние «на чём прервали» уходит в LLM
```

| Слой | Решение | Почему именно оно |
|---|---|---|
| ASR | **Groq `whisper-large-v3-turbo`** | Free-tier: 20 RPM, **2000 запросов/день, 28 800 аудио-секунд/день** (8 ч). Русский поддерживает. Быстро (LPU) |
| Резерв ASR | **Vosk small-ru** (45 МБ, Apache-2.0) | Локально, офлайн, бесплатно. WER ~22–32 % — хуже, но есть всегда |
| VAD | Silero VAD | Лёгкий, локальный, лучший в классе |
| LLM | ваш Worker → NVIDIA/OpenRouter | Уже работает |
| TTS | **edge-tts**, голос ru-RU | Бесплатно, ключ не нужен, приличный русский |
| Резерв TTS | Silero TTS (локально) / Piper | Офлайн-фолбэк |
| Wake word | **openWakeWord** на ПК | Есть готовая модель **«hey jarvis»**. CPU-дёшево. Это решает A3! |
| Память | SQLite | Ф-15 |
| Инструменты | MCP → Hermes | Ф-13/Ф-14 |

**Что закрывает:** Ф-1, Ф-2, Ф-3, Ф-4, Ф-5, Ф-8, Ф-9, Ф-11, Ф-15, Г-1…Г-5, Г-9, Г-10.
**Что доказывает:** что русский диалог с перебиванием вообще возможен на этом стеке.
**Что НЕ делает:** не проверяет ESP32 и не даёт мобильности.

> 🎯 **Это и есть ответ на «довести проект до работающего решения».** Здесь вы получаете
> работающего «Джарвиса» за считанные вечера и без паяльника. Всё остальное — улучшения.

## Ступень 2 — ESP32-S3 как спутник (недели)

**Цель:** добавить карманное устройство. Логика остаётся на ПК (или телефоне),
ESP32 — уши, рот, экран, свет.

```
[ESP32-S3 N16R8 + INMP441 + MAX98357A + OLED + WS2812]
        │ Wi-Fi (дома — LAN; вне дома — хотспот 2,4 ГГц)
        │ WebSocket, аудио в Opus
        ▼
[Оркестратор со Ступени 1 — тот же код, переехал на сервер]
```

**Ключевые решения, которые убирают риски v1:**

1. **Прошивка:** `78/xiaozhi-esp32` (MIT), board-конфиг на основе **`bread-compact-wifi`**
   (ESP32-S3 + OLED 128×64 + I2S-микрофон + I2S-усилитель — почти точная ваша схема).
   Своя конфигурация — по `docs/custom-board.md`, веб-генератор ассетов — `xiaozhi-assets-generator`.
2. **Кодовое слово (A3):** НЕ воюем с русским WakeNet. Два рабочих варианта:
   - **вариант «просто»:** штатное английское/китайское слово из прошивки (например `Hi ESP`),
     а «Джарвис» — цель на потом;
   - **вариант «правильно»:** wake word живёт на хабе (openWakeWord, модель **«hey jarvis»**),
     спутник стримит аудио постоянно. На домашнем Wi-Fi это нормально; так же умеет
     Home Assistant (server-side wake word).
3. **Перебивание (A4):** включаем AFE/AEC на S3 как улучшение, но **критерием выхода
   не делаем**. План Б — push-to-talk (кнопка). ТЗ прямо разрешает пожертвовать (приоритет 5).
4. **Питание (B1):** **IP5306** (или модуль с power-path), а не голый TP4056.
5. **Второй дисплей (B5):** вместо второго экрана — **светодиодное кольцо WS2812**
   как индикатор состояния. Один экран OLED. Это дешевле и не требует C++.
6. **Пины (B4):** учесть, что octal-PSRAM N16R8 занимает GPIO 33–37.

**Что закрывает:** Ф-2, Ф-6 (частично), Ф-7, Ф-10, Ф-11, Ф-12, Г-6, Г-7, Г-8, Г-11, Г-12.

## Ступень 3 — Мобильность: «вне дома» (выбрать один путь)

Здесь закрывается Г-8 и решается треугольник A1. Три пути, в порядке предпочтения:

### Путь 3A — свой сервер в облаке, бесплатно навсегда (предпочтительный)
**Oracle Cloud Always Free:** ARM 4 ядра / 24 ГБ / 200 ГБ, бессрочно.
- Тянет `xiaozhi-esp32-server` с локальным ASR с огромным запасом.
- Плюсы: полностью свой сервер, свои модели, свои ASR/TTS, работает откуда угодно.
- Минусы: нужна банковская карта для верификации, из РФ может потребоваться VPN,
  ARM-инстансы иногда «заняты».

### Путь 3B — ваш Cloudflare Worker как транспорт
У вас уже есть Worker с ключами. Worker + Durable Object умеет держать WebSocket.
Оркестратор остаётся на ПК, но доступен снаружи через Worker.
- Плюсы: 0 ₽, использует то, что уже работает.
- Минусы: ПК должен быть включён; нужна аккуратная реализация WS-прокси.

### Путь 3C — чужое облако xiaozhi.me
Быстро, но: русский ASR/TTS не проверен, MCP-точка в free-консоли не подтверждена,
голос уходит третьей стороне, задержка через Китай.
- Использовать как **быструю проверку железа** (этап M0), не как финал.

> **Рекомендация:** v1 = **3A (Oracle)**, резерв = **3B (Worker)**.
> **3C** — только как временный тест на первом дне работы с железом.

## Итоговая схема v2 (целевая)

```
┌───────────────────────────┐
│ ESP32-S3 N16R8            │  ← уши, рот, экран, свет (Ступень 2)
│ INMP441 · MAX98357A · OLED│
│ WS2812 · IP5306 · Li-Pol  │
└─────────────┬─────────────┘
              │ Wi-Fi 2,4 ГГц, WebSocket, Opus
              ▼
┌───────────────────────────────────────────────┐
│ ОРКЕСТРАТОР (тот же Python-код со Ступени 0–1) │
│  SileroVAD · ASR(Groq Whisper) · LLM(Worker)  │
│  TTS(edge-tts) · 3D-Speaker · SQLite · MCP    │
│  ── дома: ПК  ── вне дома: Oracle Cloud       │
└─────────────┬─────────────────────────────────┘
              │ исходящее соединение (туннель не нужен)
              ▼
┌───────────────────────────────────────────────┐
│ ПК: MCP-инструменты (файлы, команды, Hermes)  │
│ allow-list · подтверждение деструктивных · лог │
└───────────────────────────────────────────────┘
```

## Что v2 сознательно НЕ делает (и почему это правильно)

| Отказались | Почему | Когда вернуться |
|---|---|---|
| Termux + proot + sherpa-onnx | Хрупко, не проверено, в критическом пути | Если очень нужна автономность без интернета |
| Русское кодовое слово на ESP32 | Нет русских моделей WakeNet/MultiNet | Когда/если появится кастомная модель |
| AEC как обязательный критерий | Акустически трудно в кармане | Как улучшение после рабочего диалога |
| Второй дисплей | Нет поддержки в прошивке, нужен C++ | Если появится свободное время |
| Локальный LLM на S3 | Физически невозможно | Никогда на S3; только на Pi 5 / VENTUNO |
| «0 ₽ любой ценой» | Ценой становится хрупкость | Oracle даёт 0 ₽ без хрупкости |
