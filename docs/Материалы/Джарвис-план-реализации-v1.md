# «Джарвис» — план реализации v1

**К ТЗ от 27 сентября 2026 г.** · версия плана 1.0 · 27.09.2026

Зафиксированные вводные:

- v1 — сервер-оркестратор в **Termux на Android**;
- целевая эволюция — **гибрид** (телефон вне дома + ПК дома);
- ориентир по форме — проект Huy Vector «Tiny Pocket AI Assistant» (ESP32-C3, латунный корпус, 841K просмотров, 27.08.2026).

---

## 0. Главное решение и три отклонения от видео-ориентира

Видео-ориентир — это ESP32-C3 + OLED 0.96″ + ручная латунная рама + **официальное облако xiaozhi.me**. Форма и компоновка оттуда берутся целиком. Три вещи копировать нельзя:

| Что у автора видео | Почему нам нельзя | Что берём вместо |
|---|---|---|
| ESP32-C3 | ESP-SR (WakeNet + AFE) официально работает на **ESP32 и ESP32-S3**; C3 в списке поддерживаемых нет. Значит, на C3 нет локального кодового слова (Ф-3) и нет AEC → нет надёжного перебивания (Ф-4) | **ESP32-S3 N16R8** (8 МБ PSRAM нужны аудиопроцессору) |
| Облако xiaozhi.me | Нельзя подключить свой источник моделей (Ф-8/Г-9); есть квота и платные тарифы, то есть 0 ₽ не гарантирован (Ф-9/Г-10) | **Свой сервер** xiaozhi-esp32-server |
| Латунная рама | Красиво, но пайка каркаса вручную не воспроизводима и не дешевле | 3D-печать (Ф-12), форма — по мотивам |

## 1. Архитектура v1

```
[Джарвис: ESP32-S3 + OLED 0.96" + WS2812 + Li-Pol]
        │  Wi-Fi (точка доступа телефона)
        │  WebSocket, аудио в Opus
        ▼
[Сервер-оркестратор — Termux → proot-distro Ubuntu]
        ├── SileroVAD      — режет поток по тишине
        ├── SherpaASR      — речь → текст (русская модель)
        ├── LLM            — OpenAI-совместимый, free-tier
        ├── EdgeTTS        — текст → речь (ru-RU)
        ├── 3D-Speaker     — «кто говорит» → основа для Г-18
        └── MCP-шлюз
                 │  исходящее соединение (туннель не нужен)
                 ▼
        [MCP-агент на Windows-ПК: файлы, команды, запуск программ]
```

Ключевое свойство архитектуры: **прошивка устройства знает ровно один адрес**. Смена ASR / LLM / TTS — это правка конфига на сервере; устройство не перепрошивается. Именно это и означает Ф-8 / Г-9.

## 2. Стек: что выбрано и почему

| Слой | Решение | Обоснование |
|---|---|---|
| Оркестратор | `xinnan-tech/xiaozhi-esp32-server` (Python), установка **из исходников** | В документации проекта описаны Docker и source. Docker в Termux недоступен → ставим из исходников |
| ASR | **SherpaASR** (sherpa-onnx) + русская модель | Локальные ASR в сервере — FunASR и SherpaASR. FunASR ориентирован на китайский/английский, поэтому для русского берём sherpa-onnx. **Первый технический риск плана — проверить на M2** |
| VAD | **SileroVAD** | Единственный вариант в сервере; локальный, бесплатный |
| TTS | **EdgeTTS**, голос ru-RU | Ключ не нужен, указан как бесплатный |
| LLM | Любой OpenAI-совместимый. Из бесплатных в списке сервера — Zhipu glm-4-flash и Gemini | Ф-8/Г-9 = поле `base_url`. Через него же подключаются :free-модели OpenRouter |
| Голос владельца | **3D-Speaker** | Уже встроен: работает параллельно с ASR и передаёт «кто говорит» в LLM. Готовое решение для Г-18, которое в ТЗ отложено в Ф-17 |
| Память | `mem_local_short` | Локальная, бесплатная (Ф-15) |
| Инструменты | MCP: клиентский, серверный и «MCP-точка доступа» | Управление ПК — штатная возможность cloud-side MCP, а не самоделка |
| Прошивка | `78/xiaozhi-esp32`, лицензия **MIT** | Требует **ESP-IDF ≥ 6.0.1** (рекомендуется 6.1). IDF 5.x больше не поддерживается |

Требования к серверу из документации проекта:

| Вариант | CPU | RAM |
|---|---|---|
| Только API (без локального ASR) | 2 ядра | 2 ГБ |
| С локальным ASR | 2 ядра | 4 ГБ |

Оценка 4 ГБ относится к FunASR; sherpa-onnx с компактной русской моделью существенно легче, поэтому на телефоне реально уложиться в меньшее. Замер — на M2.

## 3. Этапы и критерии выхода

| Этап | Что делаем | Критерий выхода | Закрывает |
|---|---|---|---|
| **M0** | Любая ESP32-S3 devkit + штатная прошивка + xiaozhi.me. Убедиться, что устройство слышит и говорит | Сквозной диалог с официальным облаком | Проверка железа и аудиотракта |
| **M1** | Termux → proot-distro Ubuntu → сервер из исходников. Телефон и устройство в сети точки доступа | Устройство подключается к своему серверу и отвечает | Г-8 |
| **M2** | Русский ASR (sherpa-onnx) + EdgeTTS ru-RU | 8 из 10 коротких фраз распознаны верно | Г-2, Г-3, Г-9 |
| **M3** | Своё кодовое слово | Реакция на «Джарвис» индикацией | Ф-3, Г-1 |
| **M4** | AFE/AEC: включить аудиопроцессор, разнести микрофон и динамик | Перебивание голосом работает | Ф-4, Г-5 |
| **M5** | Аккумулятор, зарядка, корпус | 2 часа работы, зарядка по USB, габариты | Г-6, Г-7, Г-11, Г-12 |
| **M6** | MCP-агент на ПК, ограничения области, журнал | Файловые операции и запуск программ; выход за песочницу блокируется | Г-13…Г-17, Г-19 |
| **M7** | Память диалога | Контекст сохраняется между сессиями | Ф-15 |

Порядок принципиален: **M0 → M1 → M2 раньше корпуса и батареи.** Иначе получится красивая коробка, которая не разговаривает.

## 4. Сервер в Termux — конкретика

### 4.1 Почему proot-distro, а не просто Termux

Termux работает на Bionic (libc Android), а не на glibc. Колёса pip под Linux ARM64 (`manylinux…aarch64`) — в том числе для onnxruntime и sherpa-onnx — на Bionic не устанавливаются. Решение: поднять внутри Termux полноценный Ubuntu через `proot-distro` и работать в нём. Оверхед на трансляции системных вызовов для задачи «VAD + ASR» приемлем.

### 4.2 Порядок установки

```bash
pkg update && pkg install proot-distro termux-api
proot-distro install ubuntu
proot-distro login ubuntu

# внутри Ubuntu:
apt update && apt install -y python3 python3-venv python3-pip git ffmpeg
git clone https://github.com/xinnan-tech/xiaozhi-esp32-server
cd xiaozhi-esp32-server
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
```

> Точные пути и файл зависимостей сверить с `docs/Deployment.md` — там два варианта: минимальная установка (без БД) и полная (с БД и веб-консолью). Для v1 достаточно минимальной.

### 4.3 Чтобы Android не убил сервер

- `termux-wake-lock` — не даёт системе усыпить Termux;
- сервер запускать в `tmux` (или `screen`), чтобы он жил после закрытия сессии;
- в настройках Android снять оптимизацию батареи для Termux и разрешить фоновую работу;
- автозапуск — через приложение Termux:Boot.

### 4.4 Что задать в конфиге (по смыслу, ключи сверить с актуальной версией)

| Параметр | Значение |
|---|---|
| Транспорт | WebSocket (в v1; MQTT+UDP — если понадобится экономия трафика) |
| ASR | SherpaASR, русская модель, локальный путь |
| VAD | SileroVAD |
| TTS | EdgeTTS, голос ru-RU |
| LLM | OpenAI-совместимый: `base_url`, ключ, модель |
| Память | `mem_local_short` |
| Intent | `function_call` (быстрее, рекомендуется авторами) |
| Voiceprint | 3D-Speaker — включить под Г-18 |
| MCP | включить точку доступа для ПК |

## 5. Прошивка устройства

- Сборка из `78/xiaozhi-esp32` (MIT) на **ESP-IDF 6.1**.
- Основа — существующая board-конфигурация под наш набор: в репозитории **138 конфигураций плат и 171 вариант сборки**, ближайшая — вариант «ESP32-S3 + I2S-микрофон + I2S-усилитель». Своя конфигурация делается по `docs/custom-board.md`.
- Что меняем: пины (микрофон, усилитель, OLED, WS2812, кнопка), адрес сервера, набор ассетов.
- Кастомные ассеты — включая кодовое слово, шрифты и эмодзи — генерируются веб-инструментом `78/xiaozhi-assets-generator`.

## 6. Аудиотракт — где на самом деле решается Ф-4

Перебивание (Ф-4) — не «настройка», а следствие трёх вещей:

1. **Чип.** AFE с акустическим эхоподавлением входит в ESP-SR, который поддерживает ESP32 и ESP32-S3. На C3 его нет.
2. **Опорный сигнал.** AEC вычитает из микрофона то, что устройство само играет. Опорный сигнал берётся цифровым — из того же I2S-потока, что уходит в усилитель. Поэтому цифровой микрофон + цифровой I2S-усилитель дают чистый референс без второго микрофона.
3. **Механика.** Микрофон и динамик разносятся, корпус не создаёт акустической обратной связи (это уже требование п. 4.2 ТЗ).

Практический вывод: **ESP32-S3 N16R8 + I2S-микрофон + I2S-усилитель + включённый аудиопроцессор** — минимальная конфигурация, на которой Ф-4 достижимо. Проверка — на M4.

## 7. Управление ПК и безопасность (Г-13…Г-19)

- **Транспорт.** MCP-точка доступа: ПК сам подключается **исходящим** соединением к оркестратору. Не нужен статический IP и проброс портов, и это работает, когда устройство вне дома → Г-16.
- **Г-17 (ограничение области).** На стороне агента — allow-list папок и команд. Всё, что вне списка, отклоняется до выполнения.
- **Г-18 (только владелец).** Встроенный 3D-Speaker передаёт «кто говорит» в LLM. Для управления ПК дополнительно требуем совпадения голоса с эталоном владельца. Дешёвая промежуточная мера — PIN-фраза в запросе.
- **Г-19 (журнал).** Сервер логирует каждый вызов инструмента; журнал лежит на телефоне и не требует внешних сервисов.
- **Деструктивные операции** (удаление, перезапись) — обязательное голосовое подтверждение.

## 9. Риски и обходы

| Риск | Вероятность | Обход |
|---|---|---|
| Русская модель в SherpaASR не заводится или даёт низкое качество | Средняя | Проверять на M2 первым делом. Обход: внешний ASR с бесплатной квотой; либо в гибриде — ASR на домашнем ПК |
| Android выгружает Termux | Высокая | wake-lock + снятие оптимизации батареи + tmux. Резерв — второй профиль на ПК |
| Телефон не тянет VAD + ASR + стриминг ответа | Средняя | Локально только VAD и ASR, LLM/TTS — через API. Замер батареи и температуры |
| Кодовое слово «Джарвис» на русском не генерируется штатным WakeNet | Средняя | Использовать MultiNet (распознавание командных слов) как движок кодового слова — известный приём в сообществе |
| Перебивание не работает без хорошего разноса микрофона и динамика | Средняя | Разнести максимально в корпусе. При провале — перебивание по кнопке (временная мера; Г-5 формально не закрыт) |
| Лимиты бесплатного LLM (RPM/RPD) ломают Г-4 | Средняя | Держать 2–3 провайдера и переключать `base_url`; длинные задачи — на ПК-агент |
| Телефон занят сервером и им нельзя нормально пользоваться | Низкая | Ограничить одной сессией; не поднимать сервер при низком заряде |
| **Лицензия сервера не подтверждена** | — | **Проверить файл `LICENSE`** в `xinnan-tech/xiaozhi-esp32-server` — в README тип не указан. У прошивки MIT подтверждён |

## 10. Что в ТЗ нужно доуточнить

1. **Г-2** — не заданы расстояние до микрофона, уровень шума, число дикторов.
2. **Г-4** — не сказано, сколько попыток и как считать (медиана/среднее).
3. **Г-6** — не задан режим работы (ожидание / диалог / постоянно активный Wi-Fi). Без этого ёмкость батареи не выбирается.
4. **Г-11** — нет числовых габаритов и массы.
5. **Поведение при сбоях** — нет сети, лимит API исчерпан, сервер недоступен. Сейчас не описано вообще.
6. **Аутентификация устройства на сервере** — иначе Г-17 и Г-19 обходятся любым, кто знает адрес.
7. **Ф-17 против Г-18** — распознавание владельца отложено в «следующие версии», но требуется как критерий второго этапа. Предлагаю **перенести Ф-17 в первую версию**: в сервере это уже есть (3D-Speaker), стоимость — ноль.
8. **Г-16 против п. 2** — управление ПК требует включённого ПК. Записать как условную функцию, а не как противоречие.

## 12. После v1
